# 问答脚本

凭据检查完成后三轮提问，每轮最多 3 题。用户已经说过的信息不要重复问；能从上下文推断的先推断，然后在下一题里顺带确认。

重要：**所有数值都必须落到用户的明确回答上**。选项里的建议值只是「让用户少打字」，不代表可以默认采用。

---

## 第零轮：凭据（静默检查，缺失才问）

先跑 `node scripts/doctor.js`，两个 key 都在就不提这件事，直接进入第一轮。

缺 key 时，把对应引导转给用户，一次只问一个：

```
header: 航班数据
question: 查航班需要一个携程问道的 token，在 https://www.ctrip.com/wendao/openclaw 按页面指引申请，
          然后在终端执行 export WENDAO_API_KEY='你的 token'。设置好了告诉我，或者把 token 发我，我只用于本次查询。
options:
  - 我去申请，稍后给你
  - 我把 token 发你，这次直接用
  - 先跳过航班，只看车程和营业时间
```

高德缺 key 时：

```
header: 车程查询
question: 查驾车用时要一个高德 Web 服务 key（https://console.amap.com/dev/key/app，服务平台选「Web服务」，
          并开通「地理编码」「驾车路径规划」）。有的话按 export AMAP_API_KEY='你的 key' 设置；没有就告诉我单程大概开多久。
options:
  - 我设置 AMAP_API_KEY
  - 直接告诉你分钟数（我来给）
  - 按你估算的先算，报告里标注为估算
```

要点：

- 先讲用途（这个 key 换到什么数据），再给变量名和申请地址。
- 用户把 key 发在对话里时，用内联环境变量只传给本次进程，之后不再复述 key 的内容。
- 用户选「跳过航班」时停下来说明：没有航班数据就算不出组合，缺的这一步无法用其他信息替代。

## 第一轮：目的地与接驳（必须先完成并确认）

需要拿到：

| 项 | 问法 | 备注 |
|---|---|---|
| 雪场全名 | 「你打算去哪个雪场？」 | 同一城市常有多个雪场，必须确认到具体度假区 |
| 出发城市 / 机场 | 「从哪个城市出发？有偏好的机场吗？」 | 一线城市多机场，邻近城市可能是隐藏选项 |
| 出行人数 | 只影响总价，不影响单价，可放在后面顺带问 | |

拿到雪场名称后自己去查（不要问用户）：

- 最近的到达机场是哪个
- 机场到雪场驾车用时 → `scripts/amap_route.js`
- 日场 / 夜场营业时间、夜场休息日 → 官方公示

**然后必须输出这张确认卡**，用 AskUserQuestion 让用户点确认：

```
行程骨架确认
─────────────
出发      <城市> <机场名>（<三字码>）
到达      <城市> <机场名>（<三字码>）
雪场      <雪场全名>
单程车程  驾车 <X> 分钟，加 <Y> 分钟预留 → 按 <X+Y> 分钟计
日场      <起>–<止>（<Z> 小时）
夜场      <起>–<止>，按 <权重> 折算；<周几>不开放
─────────────────
以上无误就开始算行程？
```

选项给：`确认无误` / `车程要改` / `营业时间要改` / `换个雪场`。

> 车程预留的默认策略：**+20% 且至少 +15 分钟**。若用户提到冬季山路、夜间抵达、需要装防滑链，改成 +30% 以上，并在卡里写明。

## 第二轮：时间范围与预算（3 题）

### 题 1　出行时间范围

```
header: 出行时间
question: 这次想比较哪几个时间段？
options:
  - 一个周末（只出 1 份方案）
  - 两个相邻周末（可横向对比，推荐）
  - 连续假期（春节/元旦等，行程可更长）
```
两个以上时，要求用户给出具体日期，或自己按「第 N 个周末」推算后**回读给用户确认**（周末定义、是否含周五晚出发要说清）。

### 题 2　住宿预算

```
header: 住宿预算
question: 住宿按每晚多少算？雪场和转机城市分开给。
options:
  - 雪场 <A> / 转机 <B>（经济型）
  - 雪场 <C> / 转机 <D>（舒适型）
  - 雪场 <E> / 转机 <F>（度假型）
```

**两个价格分开问**：转机城市机场周边的过夜价与雪场差异较大，各自独立取值。

如果用户只给了一个数，追问：「这个价是雪场的还是转机城市的？另一个按多少算？」

### 题 3　年假档位

```
header: 年假档位
question: 最多能请几天年假？想比较哪几档？
options:
  - 0 / 0.5 / 1 / 2 天（四档全比较，推荐）
  - 只能 0 天（周末往返）
  - 最多 1 天
  - 最多 2 天
```

## 第三轮：口径确认（3 题）

### 题 1　税费口径

```
header: 税费
question: 机票税费按每航段多少算？（机建 + 燃油合计）
options:
  - ¥150 / 航段（常见口径）
  - ¥90 / 航段（燃油低位）
  - 你帮我查实时标准
```

说明**税费按航段计收**：中转单程 2 段、往返 4 段。

### 题 2　请假切点

```
header: 请假切点
question: 请假怎么算？默认口径如下，需要改吗？
options:
  - 沿用默认（13:30 前出发算 1 天、13:30–19:30 算 0.5 天、19:30 后算 0 天；返程 10:00 前落地算 0 天）
  - 我们公司考勤不同，我来指定
```

### 题 3　（可选）附加约束

```
header: 附加约束
question: 有没有必须满足的条件？
options:
  - 无，只看性价比
  - 只要直飞（不接受中转）
  - 必须带雪具（要考虑行李费）
  - 单程总耗时不超过 X 小时
```

「必须带雪具」不改变模型，结论里单列行李托运费。

---

## 何时停止提问

三个条件都满足就可以开始跑数：

1. 行程骨架已确认
2. 住宿两个价、税费单价、请假档位、请假切点都有明确数值
3. 平票时的取舍偏好已知（或用户明确说不在意）

## 用户答不上来时

- 「大概多少」→ 给 2–3 个具体数字让用户选。
- 「你看着办」→ 说「我先按 A 算，报告里会标注这是假设值，你可以随时让我改成 B」，然后在报告头部标注该值为假设。
- 完全没有概念（比如从没去过该雪场）→ 先查官方公示再复述给用户确认；拿不到就停下来问。
